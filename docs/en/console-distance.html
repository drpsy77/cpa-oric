CP/A remote console

The Mac (or a phone's browser) types and reads in place of the real Oric's keyboard and screen, through the LOCI and its WiFi modem. Specification: docs/en/console-distance.md. Nothing is coded.

Short answers

Who leads? For the screen, the Mac leads: it asks, the Oric only answers. The Oric never sends anything unasked.

Who finds the changed rows? The Mac. It keeps a copy of the 28 rows and computes their checksums itself. It asks for the Oric's (S), compares both series, then asks one by one for the rows that differ (L n). The Oric remembers nothing of what it has sent.

When? As soon as a key has gone, the Mac asks for the cursor row (fast echo, 0.1 to 0.15 s). Then a full cycle; then every 0.5 s when idle, and again at once as long as a cycle finds changed rows.

No local echo: a key typed on the Mac is not displayed there by itself. It goes to the Oric, whose program decides what to display, and the Mac shows what the Oric displayed, like telnet or ssh. Whether the key comes from the Mac or from the Oric's keyboard, the Mac simply sees the Oric's screen.

Both ways? The TCP connection stays open both ways as long as the console is on. Mac → Oric: keys and requests, whenever it wants. Oric → Mac: only answers (S and L frames).

Faithfulness: the copy holds the exact bytes of SCREEN, attributes included (ink, paper, alternate font, blinking, double height). The page draws them with CP/A's font, following the same rules as the ULA. The Mac draws the cursor from the S frame.

Limits: a state that does not last until the next cycle is never seen (only the final state arrives). Full-screen HIRES is not sent, and in SPLIT only rows 16 to 27 are.

Messages exchanged

The Mac's loop (remote.py)

copy[0..27]    = 28 rows of 40 bytes (empty at start)
loop:
    if keys are waiting:
        send them                       ($FE k for each)
        fast echo: send $FD 'L' cy (cursor row, from the last S frame)
                   copy[cy] = the 40 bytes received
    send $FD 'S'; wait for the S frame (1 s at most, otherwise ask again)
    for n from 0 to 27:
        if received_checksum[n] != fletcher(copy[n]):
            send $FD 'L' n; wait for the L frame; copy[n] = its 40 bytes
    if at least one row has changed: start again at once
    otherwise: wait 0.5 s, or the next key
the web page reads the copy every 0.1 s (GET /ecran) and redraws
